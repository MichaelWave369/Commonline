# P0-l Live Media Acceptance Harness

Status: candidate end-to-end media acceptance rung

Wire schema: unchanged at `p0-k.1`  
Storage schema: unchanged at `p0-k.1`

P0-l does not add a new room capability, source class, or durable state transition. It turns the P0-j/P0-k live-media contract into a repeatable three-browser acceptance test.

The governing distinction is:

```text
TEST EVIDENCE
    ≠
ROOM AUTHORITY
```

Acceptance evidence proves that the implementation obeyed a routing contract during a test run. It does not create a Commonline acceptance receipt, grant authority, or become durable room history.

## Acceptance matrix

The primary test opens three independent Chromium browser contexts:

```text
Alice
  publishes human-microphone
  publishes sound-effect

Bob
  subscribes Alice microphone only

Charlie
  subscribes Alice sound-effect only
```

Expected initial routing:

| Receiver | Alice microphone | Alice sound effect |
|---|---|---|
| Bob | receive | no Consumer |
| Charlie | no Consumer | receive |

The harness then changes subscriptions live without restarting the room or SFU:

- Bob unsubscribes from Alice microphone
- Charlie subscribes to Alice microphone
- Bob subscribes to Alice sound effect
- Charlie unsubscribes from Alice sound effect

Expected final routing:

| Receiver | Alice microphone | Alice sound effect |
|---|---|---|
| Bob | no Consumer | receive |
| Charlie | receive | no Consumer |

## Packet evidence

The browser polls `mediasoup-client` Consumer stats and exposes, per source:

- Consumer ID
- source ID
- source kind
- owner
- track ready state
- inbound RTP packets received
- inbound RTP bytes received
- jitter when available
- observation timestamp

The Playwright test requires live subscribed Consumers to report non-zero inbound RTP packet and byte counts.

For non-subscribed source/receiver pairs, the harness requires that no Consumer surface exists at all.

This proves a stronger statement than merely checking the UI subscription label:

```text
subscription exists
      ↓
Consumer exists
      ↓
inbound RTP observed
```

and:

```text
no subscription
      ↓
no Consumer
```

## Real browser path

The CI job launches:

- the real Commonline Node room service
- the real mediasoup Worker and Router
- the Vite browser app
- three isolated Chromium contexts
- browser fake microphone capture
- the real Web Audio sound-effect source
- the real mediasoup-client transport path

Chromium is launched with fake microphone and autoplay flags so CI can exercise media without physical hardware.

The sound-effect cue is still generated by Web Audio in Alice's browser and routed through the real SFU Producer/Consumer path.

## Identity and grants

Each browser context receives separate localStorage, sessionStorage, IndexedDB, and cryptographic identity state.

The contexts join as ordinary human participants and receive the same P0 room grants as normal participants.

The harness does not bypass identity challenge-response, group membership, SPEAK checks, RECEIVE_MEDIA checks, source policy, subscription creation, or SFU authorization.

## Evidence artifact

A successful run writes:

```text
test-results/p0l-media-acceptance.json
```

with:

- test identity
- generation time
- intended initial/final subscription matrices
- per-source packet/byte evidence for subscribed paths
- explicit zero Consumer counts for denied paths

The Playwright HTML report, traces/screenshots/videos on failure, and the JSON evidence file are uploaded as CI artifacts.

These artifacts are test evidence only. They are not inserted into Commonline SQLite or room event history.

## Failure meaning

A P0-l failure should be interpreted narrowly:

- missing Consumer when subscribed
- Consumer present when unsubscribed
- subscribed Consumer receives no RTP
- live subscription removal fails to destroy the route
- live subscription creation fails to establish the route
- browser/SFU startup or identity flow fails

It does not automatically imply durable room corruption.

## Schema decision

P0-l intentionally leaves wire and storage schemas at `p0-k.1`.

The rung adds observability and acceptance automation, not a new protocol contract. Bumping durable/wire metadata merely to name a test harness would create meaningless migration churn.

## Next rung

Once P0-l is green, Commonline has repeatable evidence for:

```text
policy
  → source
  → subscription
  → SFU Consumer
  → inbound RTP
```

That makes it safer to activate the next reserved source class, with agent voice or shared music remaining separate design decisions.
